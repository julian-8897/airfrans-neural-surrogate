# Check the Transolver forward implementation

After protocol approval, run the check in the registered qualification job on a full A100. Use the [complete training stage and its normaliser](original-data-staging.md). The job environment needs CUDA-enabled PyTorch, PyVista, `timm` and `einops`. Preserve the environment with the run record.

```bash
python -m airfoil_surrogate.models.transolver_parity \
  /path/to/pinned/Transolver.py /path/to/train /path/to/normaliser.json \
  --case airFoil2D_SST_31.283_-4.156_0.919_6.98_14.32 \
  --out "$EXP_OUT/transolver-parity.json"
```

Pass the authors' `Airfoil-Design-AirfRANS/models/Transolver.py` at revision `75e0f67643806a81cd1d3f6adc88dd8c02416fe7`. The command verifies the source SHA-256 before execution. It initialises the reference at seed 0 and copies its forward parameters to the local model. The JSON lists the mapped and unused weights and the grid generated by the local model. [Pinned Transolver source](https://github.com/thuml/Transolver/blob/75e0f67643806a81cd1d3f6adc88dd8c02416fe7/Airfoil-Design-AirfRANS/models/Transolver.py).

The two models receive the same positional and normalised input tensors. The check uses two disjoint 4,096-node subsets and the full original mesh, with FP32 matmul at its highest precision. The JSON records maximum absolute and RMS differences in each channel. When a forward check exceeds the proposed tolerances, the command writes the discrepancies and exits with status 1.
